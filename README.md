# AdventureWorksMicroservices
AdventureWorksMicroservices is a project to implement a microservices architecture using ASP.NET Core and MS SQL Server. The goal of the project is to provide an API interface for managing data from the AdventureWorks database using Docker and CI/CD techniques.

## Objectives
- Build an API for retrieving, adding, and updating data in the AdventureWorks database.
- Use a Microservices architecture to decouple the services.
- Set up CI/CD using Jenkins.

## Technologies Used
- **ASP.NET Core**: To build the REST API.
- **MS SQL Server**: To manage the database.
- **Docker**: To run the application inside containers.
- **Jenkins**: To set up the CI/CD pipeline.

## Step 3: Database Setup (MS SQL Server)

### Download AdventureWorksLT Database

1. Download the AdventureWorksLT2022 backup file from [Microsoft GitHub](https://github.com/Microsoft/sql-server-samples/releases)
2. Save it to: `C:\Program Files\Microsoft SQL Server\MSSQL16.MSSQLSERVER\MSSQL\Backup\`

### Restore Database in SSMS

1. **Open SSMS** and connect to your SQL Server instance
2. **Right-click Databases** → **Restore Database**
3. **Select Device** → **Add** → Browse to the `.bak` file
4. **Click OK** → **OK** to restore
5. Verify database appears in Object Explorer

### Create SQL User for Application

```sql
-- Create login
CREATE LOGIN AppUser WITH PASSWORD = 'YourSecurePassword123!';

-- Switch to AdventureWorksLT2022 database
USE AdventureWorksLT2022;
GO

-- Create user
CREATE USER AppUser FOR LOGIN AppUser;

-- Grant permissions
ALTER ROLE db_datareader ADD MEMBER AppUser;
ALTER ROLE db_datawriter ADD MEMBER AppUser;
GO
```

### Update appsettings.json

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Database=AdventureWorksLT2022;User Id=AppUser;Password=YourSecurePassword123!;TrustServerCertificate=True;"
  },
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*"
}
```

**⚠️ Security Note:** Never commit actual passwords to Git. Use User Secrets or environment variables in production.

## Step 4: Entity Framework Configuration

### Install Required NuGet Packages

```bash
# In Package Manager Console or terminal in project directory
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet add package Microsoft.EntityFrameworkCore.Tools
dotnet add package Microsoft.EntityFrameworkCore.Design
```

### Create DbContext

Create `Data/ApplicationDbContext.cs`:

```csharp
using Microsoft.EntityFrameworkCore;
using MicroservicesAdventureWorks.API.Models;

namespace MicroservicesAdventureWorks.API.Data
{
    public class ApplicationDbContext : DbContext
    {
        public ApplicationDbContext(DbContextOptions<ApplicationDbContext> options)
            : base(options)
        {
        }

        // Add your DbSets here
        // Example: public DbSet<Product> Products { get; set; }
    }
}
```

### Configure Services in Program.cs

```csharp
using Microsoft.EntityFrameworkCore;
using MicroservicesAdventureWorks.API.Data;

var builder = WebApplication.CreateBuilder(args);

// Add services to the container.
builder.Services.AddDbContext<ApplicationDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));

builder.Services.AddControllers();
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

var app = builder.Build();

// Configure the HTTP request pipeline.
if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

app.UseHttpsRedirection();
app.UseAuthorization();
app.MapControllers();

app.Run();
```

### Test Database Connection

Create a simple controller to verify connection:

```csharp
using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;
using MicroservicesAdventureWorks.API.Data;

namespace MicroservicesAdventureWorks.API.Controllers
{
    [ApiController]
    [Route("api/[controller]")]
    public class HealthController : ControllerBase
    {
        private readonly ApplicationDbContext _context;

        public HealthController(ApplicationDbContext context)
        {
            _context = context;
        }

        [HttpGet]
        public async Task<IActionResult> Get()
        {
            try
            {
                await _context.Database.CanConnectAsync();
                return Ok(new { status = "Healthy", database = "Connected" });
            }
            catch (Exception ex)
            {
                return StatusCode(500, new { status = "Unhealthy", error = ex.Message });
            }
        }
    }
}
```

## Step 5: Docker Configuration

### Create Dockerfile

Create `Dockerfile` in project root:

```dockerfile
# Stage 1: Build
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# Copy csproj and restore dependencies
COPY ["MicroservicesAdventureWorks.API/MicroservicesAdventureWorks.API.csproj", "MicroservicesAdventureWorks.API/"]
RUN dotnet restore "MicroservicesAdventureWorks.API/MicroservicesAdventureWorks.API.csproj"

# Copy everything else and build
COPY . .
WORKDIR "/src/MicroservicesAdventureWorks.API"
RUN dotnet build "MicroservicesAdventureWorks.API.csproj" -c Release -o /app/build

# Stage 2: Publish
FROM build AS publish
RUN dotnet publish "MicroservicesAdventureWorks.API.csproj" -c Release -o /app/publish /p:UseAppHost=false

# Stage 3: Runtime
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS final
WORKDIR /app
EXPOSE 80
EXPOSE 443
COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "MicroservicesAdventureWorks.API.dll"]
```

### Create docker-compose.yml

```yaml
version: '3.8'

services:
  api:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "8000:80"
      - "8001:443"
    environment:
      - ASPNETCORE_ENVIRONMENT=Development
      - ASPNETCORE_URLS=http://+:80
      - ConnectionStrings__DefaultConnection=Server=host.docker.internal;Database=AdventureWorksLT2022;User Id=AppUser;Password=YourSecurePassword123!;TrustServerCertificate=True;
    depends_on:
      - sqlserver

  sqlserver:
    image: mcr.microsoft.com/mssql/server:2022-latest
    environment:
      - ACCEPT_EULA=Y
      - SA_PASSWORD=YourStrong@Passw0rd
    ports:
      - "1433:1433"
    volumes:
      - sqlserver-data:/var/opt/mssql

volumes:
  sqlserver-data:
```

### Build and Run with Docker

```bash
# Navigate to solution directory
cd MicroservicesAdventureWorks

# Build Docker image
docker-compose build

# Start containers
docker-compose up -d

# View logs
docker-compose logs -f

# Test API
curl http://localhost:8000/api/health

# Stop containers
docker-compose down
```

## Step 8: Jenkins Job Configuration

### Configure Git in Jenkins

1. **Navigate to:** Manage Jenkins → Tools
2. **Scroll to Git**
3. **Git installations:**
   - Name: `Default`
   - Path to Git executable: `C:\Program Files\Git\cmd\git.exe`
4. **Click Save**

### Create GitHub Personal Access Token (PAT)

1. **Go to GitHub** → Settings → Developer settings → Personal access tokens → Tokens (classic)
2. **Generate new token (classic)**
3. **Token name:** `Jenkins Integration`
4. **Select scopes:**
   - ✓ `repo` (Full control of private repositories)
   - ✓ `admin:repo_hook` (Full control of repository hooks)
   - ✓ `workflow` (Update GitHub Action workflows)
   - ✓ `admin:org` → `read:org` (Read org and team membership)
5. **Generate token** and **copy it immediately** (you won't see it again!)

### Add GitHub Credentials to Jenkins

1. **Navigate to:** Manage Jenkins → Credentials
2. **Click:** (global) domain
3. **Add Credentials:**
   - Kind: `Username with password`
   - Username: Your GitHub username
   - Password: Paste your PAT token
   - ID: `github-credentials`
   - Description: `GitHub Personal Access Token`
4. **Create**

### Configure GitHub Server in Jenkins

1. **Navigate to:** Manage Jenkins → System
2. **Scroll to GitHub → GitHub Servers**
3. **Add GitHub Server:**
   - Name: `GitHub`
   - API URL: `https://api.github.com`
   - Credentials: Select `github-credentials`
   - Manage hooks: ✓
4. **Test connection**
5. **Save**

### Create Jenkins Job

1. **Dashboard → New Item**
2. **Enter item name:** `MicroservicesAdventureWorks-Build`
3. **Select:** Freestyle project
4. **OK**

### Configure Job

**General:**
- Description: `Build and deploy Microservices Adventure Works API`

**Source Code Management:**
- Select: `Git`
- Repository URL: `https://github.com/<your-username>/MicroservicesAdventureWorks.git`
- Credentials: Select `github-credentials`
- Branch Specifier: `*/main` (⚠️ Important: use `main` not `master`)

**Build Triggers:**
- ✓ `GitHub hook trigger for GITScm polling`

**Build Steps:**

Add **Execute Windows batch command**:

```batch
@echo off
echo ========================================
echo Starting Build Process
echo ========================================

REM Navigate to project directory
cd MicroservicesAdventureWorks.API

REM Restore dependencies

REM Build the project

dotnet build --configuration Release --no-restore

REM Run tests (if you have any)
REM echo Running tests...

REM Publish the project
echo Publishing project...
dotnet publish --configuration Release --output %WORKSPACE%\publish --no-build

echo ========================================
echo Build Completed Successfully
echo ========================================
```

**Optional - Docker Build Step:**

Add another **Execute Windows batch command**:

```batch

docker build -t microservices-adventureworks:latest .

```

## Step 10: Ngrok Setup

### Why Ngrok?

Jenkins running on `localhost:8080` is not accessible from the internet. GitHub webhooks need a public URL. Ngrok creates a secure tunnel from a public URL to your localhost.

### Install and Configure Ngrok

1. **Download ngrok** from [ngrok.com/download](https://ngrok.com/download)
2. **Extract to:** `C:\ngrok\`
3. **Create ngrok account** at [ngrok.com](https://ngrok.com/)
4. **Get your auth token** from dashboard

### Authenticate Ngrok

```bash
# Navigate to ngrok directory
cd C:\ngrok

# Authenticate
ngrok config add-authtoken YOUR_AUTH_TOKEN_HERE
```

### Start Ngrok Tunnel

```bash
# Start tunnel to Jenkins
ngrok http 8080
```

You'll see output like:
```
Session Status                online
Account                       your@email.com
Version                       3.x.x
Region                        United States (us)
Forwarding                    https://xxxx-xx-xx-xx-xx.ngrok-free.app -> http://localhost:8080
```

**Copy the HTTPS forwarding URL!** (e.g., `https://xxxx-xx-xx-xx-xx.ngrok-free.app`)

### Update GitHub Webhook

1. **Go back to GitHub webhook configuration**
2. **Update Payload URL:** `https://xxxx-xx-xx-xx-xx.ngrok-free.app/github-webhook/`
   - Replace with YOUR ngrok URL
   - Keep the `/github-webhook/` path!
3. **Save webhook**

### Keep Ngrok Running

**Important:** Every time you restart ngrok, the URL changes! You'll need to:
1. Get the new URL from ngrok
2. Update the GitHub webhook with the new URL

**Pro tip:** Ngrok paid plans offer static URLs.

## Troubleshooting

### Git Issues

**Problem:** `fatal: not a git repository`
```bash
# Solution: Initialize or clone repository
git init
# OR
git clone <repository-url>
```

**Problem:** `Permission denied (publickey)`
```bash
# Solution: Use HTTPS instead of SSH, or configure SSH keys
git remote set-url origin https://github.com/<username>/<repo>.git
```

### Database Connection Issues

**Problem:** Cannot connect to SQL Server

```bash
# Check if SQL Server is running
Get-Service MSSQLSERVER

# Start SQL Server if stopped
Start-Service MSSQLSERVER

# Test connection
sqlcmd -S localhost -U AppUser -P YourSecurePassword123!
```

**Problem:** Login failed for user

```sql
-- Verify user exists
USE AdventureWorksLT2022;
SELECT name FROM sys.database_principals WHERE name = 'AppUser';

-- Recreate user if needed
DROP USER AppUser;
CREATE USER AppUser FOR LOGIN AppUser;
ALTER ROLE db_datareader ADD MEMBER AppUser;
ALTER ROLE db_datawriter ADD MEMBER AppUser;
```

### Docker Issues

**Problem:** Docker daemon not running

```bash
# Start Docker Desktop
# Check status
docker ps

# Restart Docker service
Restart-Service docker
```

**Problem:** Port already in use

```bash
# Find process using port 8000
netstat -ano | findstr :8000

# Kill process (replace PID)
taskkill /PID <PID> /F

# Or change port in docker-compose.yml
```

### Jenkins Issues

**Problem:** Jenkins won't start

```bash
# Check Jenkins service
Get-Service Jenkins

# Start Jenkins
Start-Service Jenkins

# Check Jenkins logs
Get-Content "C:\ProgramData\Jenkins\.jenkins\jenkins.log" -Tail 50
```

**Problem:** Build fails - "dotnet not recognized"

```bash
# Add .NET SDK to PATH in Jenkins
# Manage Jenkins → System → Global properties
# Environment variables:
# Name: PATH
# Value: C:\Program Files\dotnet;$PATH
```

**Problem:** Git executable not found

- Verify Git path in Jenkins (Manage Jenkins → Tools)
- Should be: `C:\Program Files\Git\cmd\git.exe`

### Webhook Issues

**Problem:** Webhook not triggering builds

1. **Check ngrok is running:**
   ```bash
   # Ngrok must be running continuously
   ngrok http 8080
   ```

2. **Verify webhook URL in GitHub:**
   - Should be: `https://<your-ngrok-url>.ngrok-free.app/github-webhook/`
   - Note the trailing slash!

3. **Check GitHub webhook deliveries:**
   - GitHub → Repo → Settings → Webhooks
   - Click webhook → Recent Deliveries
   - Check response codes (should be 200)

4. **Verify Jenkins GitHub plugin:**
   - Manage Jenkins → Plugins
   - Ensure "GitHub plugin" is installed and enabled

**Problem:** Wrong branch building

- **Solution:** Check Branch Specifier in job config
- Should be `*/main` not `*/master` (GitHub's default changed)

### General Debugging

**Enable verbose logging in Jenkins:**
- Manage Jenkins → System Log → Add new log recorder
- Logger: `org.jenkinsci.plugins.github`
- Log level: `ALL`

**Check firewall:**
```powershell
# Allow Jenkins through firewall
New-NetFirewallRule -DisplayName "Jenkins" -Direction Inbound -Port 8080 -Protocol TCP -Action Allow
```

## Best Practices

### Security

1. **Never commit sensitive data:**
   - Use `.gitignore` for `appsettings.json`
   - Use `appsettings.Development.json` for local settings
   - Use environment variables or Azure Key Vault for production

2. **Use User Secrets in Development:**
   ```bash
   dotnet user-secrets init
   dotnet user-secrets set "ConnectionStrings:DefaultConnection" "your-connection-string"
   ```

3. **Secure Jenkins:**
   - Enable security in Manage Jenkins → Security
   - Use Matrix-based security
   - Limit anonymous access

### CI/CD Best Practices

1. **Add automated tests** to your build pipeline
2. **Use multi-stage Docker builds** (as shown) for smaller images
3. **Tag Docker images** with build numbers or Git commit SHAs
4. **Set up staging environment** before production
5. **Implement health checks** in your API

### Git Best Practices

1. **Use meaningful commit messages**
2. **Create feature branches** for new development
3. **Use Pull Requests** for code review
4. **Tag releases:** `git tag -a v1.0.0 -m "Release 1.0.0"`
